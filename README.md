# QQQ Ballast

매일 아침 미국장 종가로 신호를 계산해서 **텔레그램으로 매매 신호를 보내주는** 자동화 프로젝트입니다.
GitHub Actions가 대신 실행해 주므로 PC를 켜둘 필요가 없습니다.

> ⚠️ 이 프로젝트는 과거 데이터 백테스트에 기반한 개인용 도구입니다. 과거 성과가 미래 수익을 보장하지 않으며,
> 실제 매매와 그 결과에 대한 책임은 본인에게 있습니다.

---

## 1. 전략 한눈에 보기

| 구분 | 내용 |
|---|---|
| 코어 | **QQQ** 트랙2 — 고점 대비 -10%에서 25% 매도, -15%(또는 추세 소멸)에서 전량 매도, 이후 추세 회복 시 재진입 |
| 위성 | QQQ를 판 뒤 **남은 현금**을 TLT·GLD·XLE 중 **신호가 ON인 자산에만** 자산당 현금의 1/3씩 투자 (OFF 몫은 현금 유지) |
| 신호 시점 | 미국장 종가로 계산 |
| 체결 가정 | 다음 미국 거래일 시가 |

백테스트(2005-02~2026-09, 21.5년, 비용·이자 제외): **CAGR 15.6% / MDD -17.3% / Calmar 0.90**
(비교: QQQ 트랙2 단독 12.4% / -18.6% / 0.67)

> 알아둘 점: 체결이 하루 더 늦어지면 2008~09년 구간에서 MDD가 -30% 안팎까지 커지는 것으로 확인됐습니다.
> 신호를 받은 날 바로 실행하는 것이 중요합니다. 자세한 검증은 `QQQ_Ballast_전략_정정본.md`를 참고하세요.

## 2. 폴더 구성

```
qqq-ballast/
├─ ballast_signal.py            # 신호 계산 + 텔레그램 발송 (핵심 코드)
├─ requirements.txt             # 필요한 파이썬 라이브러리
├─ README.md                    # 이 문서
└─ .github/workflows/
   ├─ ballast.yml               # 매일 06:30(한국시간) 실행
   └─ keepalive.yml             # 예약 실행이 멈추지 않게 매월 활동 기록
```

> `.github` 폴더는 **점(.)으로 시작해서 윈도우 탐색기에서 숨김**일 수 있습니다.
> 파일 탐색기 → 보기 → 표시 → **숨긴 항목** 체크 후 확인하세요. 폴더째로 올려야 동작합니다.

## 3. 설정 방법 (처음 한 번만)

### 3-1. 텔레그램 봇 만들기
1. 텔레그램에서 **@BotFather** 검색 → 대화 시작 → `/newbot`
2. 봇 이름과 아이디(끝이 `bot`으로 끝나야 함)를 정하면 **토큰**(`123456:ABC-...`)을 알려줍니다. 복사해 두세요.
3. 방금 만든 봇을 검색해서 **아무 메시지나 한 번 보냅니다** (예: `/start`). 이 과정이 없으면 봇이 나에게 메시지를 못 보냅니다.

### 3-2. 내 chat_id 확인
브라우저 주소창에 아래 주소를 입력합니다 (`<토큰>` 부분을 내 토큰으로 바꿉니다).

```
https://api.telegram.org/bot<토큰>/getUpdates
```

화면에 나온 내용 중 `"chat":{"id":123456789,...}`의 **숫자**가 chat_id입니다.

### 3-3. GitHub 저장소 만들고 올리기
1. GitHub에서 새 저장소를 만듭니다. **Private(비공개) 권장** — 투자 신호가 공개되지 않도록.
2. GitHub Desktop으로 이 폴더(`qqq-ballast`)를 저장소에 추가하고 **Commit → Push** 합니다.
   `.github/workflows` 안의 두 yml 파일이 함께 올라갔는지 GitHub 웹에서 확인하세요.

### 3-4. 토큰을 Secrets에 등록
저장소 → **Settings → Secrets and variables → Actions → New repository secret**

| Name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 3-1에서 받은 토큰 |
| `TELEGRAM_CHAT_ID` | 3-2에서 확인한 숫자 |

토큰을 코드나 README에 직접 적어서 올리면 안 됩니다. 반드시 Secrets로만 넣으세요.

### 3-5. 테스트 실행
1. 저장소 → **Actions** 탭 → 왼쪽 **Ballast Daily Signal** 선택
2. **Run workflow** 클릭 → `dry_run`을 체크하면 텔레그램 발송 없이 실행 로그에서 메시지를 확인할 수 있습니다.
3. 로그가 정상이면 `dry_run` 체크를 끄고 한 번 더 실행해서 텔레그램에 메시지가 오는지 확인합니다.

> 워크플로가 처음에 목록에 안 보이면 Actions 탭에서 "I understand my workflows, go ahead and enable them"을 눌러 활성화하세요.

## 4. 발송 일정

- **월~토 아침 06:30 (한국시간)**, 자동 실행
- GitHub 예약 실행은 부하에 따라 **몇 분~수십 분 늦게** 시작될 수 있습니다.

| 발송일(KST) | 기준 종가 | 내용 |
|---|---|---|
| 화~금 | 전날 미국장 | 정상 신호 메시지 |
| **토** | 금요일 미국장 | 정상 신호 메시지 (다음 미국 개장일인 월요일 시가에 실행) |
| **월** | 없음 (미국장 일요일 휴장) | "신규 신호 없음, 직전 비중 유지" 짧은 안내 |
| 미국 휴장일 | 없음 | "휴장 또는 데이터 미갱신" 안내 |

마감 직후에는 야후 데이터가 늦게 반영될 수 있어서, 최신 데이터가 보이지 않으면 5분 간격으로 최대 3번 다시 확인한 뒤 발송합니다.

## 5. 메시지 읽는 법

```
📊 QQQ Ballast 신호 — 2026-09-30 종가 기준
한줄요약: QQQ 매도, GLD 매수 (2건 매매)

🔴 QQQ  0%  (전량 매도 · 손절 -15%)
⚪ TLT  0%  (OFF)
🟢 GLD  33.3%  (비중 조정)
🟠 XLE  0%  (OFF)

──────────────
💰 오늘 실행할 매매
1. QQQ 전량 매도 -75.0%p (75% → 0%)
2. GLD 추가 매수 +25.0%p (8.3% → 33.3%)
──────────────

📉 QQQ 20일 변동성 21.4% (참고용, 신호에는 미반영)

━━━ 부가 정보 ━━━
...자산별 전일대비 | 고점대비, 보유 중이면 손절선까지 남은 %

━━━ 위성 비중 변경 ━━━     ← 위성 자신의 신호가 켜지거나 꺼진 날만 표시
GLD  0% → 100%
```

| 표시 | 의미 |
|---|---|
| 🟢 | 신규 진입 / 재진입 |
| 🔴 | 청산 / 매도 |
| 🟠 | 보유 유지 (또는 비중 조정) |
| ⚪ | 미보유 |

- **비중은 계좌 전체 대비 %** 입니다. 매매 항목의 `%p`도 계좌 전체 대비 변화폭입니다.
- **위성 비중 변경**은 QQQ 비중과 무관하게, TLT·GLD·XLE 각자의 신호가 ON↔OFF로 바뀐 날만 나옵니다. (`0% → 100%` = 신호 ON, `100% → 0%` = 신호 OFF)
  QQQ 비중이 바뀌어서 위성 금액이 달라지는 경우는 위쪽 최종 비중과 "오늘 실행할 매매"에 나옵니다.
- **고점대비**는 데이터 시작(2005년) 이후 역대 최고 종가 기준이고, **손절선까지 남은 %**는 전략이 추적하는 고점(보유 중 최고 종가) 기준입니다. 두 값이 다를 수 있습니다.
- 변동성 줄은 참고용입니다. 45%를 넘으면 ⚠️ 표시가 붙지만 전략 판단에는 쓰이지 않습니다.
- TLT는 %손절 대신 **SMA20이 SMA110 밑으로 내려가면(데드크로스) 청산**하므로 "SMA 격차"를 보여줍니다.

## 6. 내 PC에서 테스트하기 (선택)

```bash
pip install -r requirements.txt

# 야후 데이터로 계산만 해보기 (발송 안 함)
python ballast_signal.py --dry-run --force

# 저장된 CSV로 백테스트 재현 확인 (qqq_us_d.csv 등 4개 파일이 같은 폴더에 있어야 함)
python ballast_signal.py --source csv --csv-dir . --check
# → CAGR 15.60% / MDD -17.34% / Calmar 0.899 (2026-09-14 데이터 기준)
```

**최초 1회 권장 검증**: 같은 날짜 기준으로 `--source csv --dry-run --force`와 `--dry-run --force`(야후)의 비중이 같은지 비교해 보세요.
CSV와 야후의 배당 조정 방식이 조금 달라서 아주 드물게 경계선에서 신호가 다를 수 있습니다.

## 7. 파라미터 위치

`ballast_signal.py` 위쪽의 `QQQ_PARAMS`, `TLT_PARAMS`, `GLD_PARAMS`, `XLE_PARAMS`, `N_SAT`에 확정값이 있습니다.
값을 바꾸면 백테스트 결과와 달라지므로, 바꾸기 전에 `--check`로 성과를 다시 확인하세요.

## 8. keep-alive (예약 실행이 멈추지 않게)

GitHub은 **공개(Public) 저장소**에서 60일 동안 활동이 없으면 예약 실행을 자동으로 멈춥니다.
`keepalive.yml`이 매월 1일에 빈 커밋을 남기고 신호 워크플로를 다시 활성화해서 이를 막습니다.
비공개 저장소는 이 규칙 대상이 아니지만 그대로 두어도 문제없습니다.
(저장소 Settings → Actions → General → Workflow permissions가 **Read and write**로 되어 있어야 빈 커밋이 올라갑니다.)

## 9. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 텔레그램 메시지가 안 옴 | Actions 실행 로그 확인 → Secrets 이름 오타, 봇에게 `/start`를 보냈는지, chat_id가 맞는지 |
| 실행은 됐는데 "데이터 미갱신" 안내가 옴 | 미국 휴장일이거나 야후 지연. 휴장이 아니면 잠시 뒤 **Run workflow**로 수동 실행 |
| 아침 6:30에 안 오고 늦게 옴 | GitHub 예약 실행 지연(정상 범위). 수십 분 이상 지연되면 Actions 탭에서 상태 확인 |
| ❌ 실행 오류 메시지가 옴 | 로그의 오류 내용 확인. 대부분 야후 일시 장애라 다음 실행에서 복구됨 |
| 몇 달째 아무 메시지가 없음 | Actions 탭에서 워크플로가 Disabled인지 확인 → Enable |
